## Reconstruction of the fitting methodology

### Method

Sequential binary logistic regression on **unscaled** `(rain_frac, log10(swe+1))`
features using the merged GMM class labels. "Sequential" means two separate binary
logistic regressions rather than a single multinomial fit:

1. **B1 model** — fit on `{snowmelt, ROS}` peaks only:
   `response = I(gmm_class == "snowmelt")`

2. **B2 model** — fit on `{ROS, rainfall}` peaks only:
   `response = I(gmm_class == "ROS")`

The decision boundary of a binary logistic model
`logit = β₀ + β₁·rain_frac + β₂·log10_swe = 0`
rearranged gives:

```
B1 form: log10_swe  = (−β₀/β₂) + (−β₁/β₂) · rain_frac
B2 form: rain_frac  = (−β₀/β₁) + (−β₂/β₁) · log10_swe
```

So the coefficients are:

```r
B1_INTERCEPT = -coef(b1_fit)[1] / coef(b1_fit)[3]   # -intercept / swe_log coeff
B1_SLOPE     = -coef(b1_fit)[2] / coef(b1_fit)[3]   # -rain_frac coeff / swe_log coeff

B2_INTERCEPT = -coef(b2_fit)[1] / coef(b2_fit)[2]   # -intercept / rain_frac coeff
B2_SLOPE     = -coef(b2_fit)[3] / coef(b2_fit)[2]   # -swe_log coeff / rain_frac coeff
```

### Exact reconstruction code

```r
# Prerequisite: run diagnostics_final.Rmd chunks 1–3 to produce gmm_data
# with columns: rain_frac, swe_log (= log10(swe_mean_mm + 1)), gmm_class

# B1 — Snowmelt vs. ROS boundary
b1_data <- gmm_data %>% dplyr::filter(gmm_class %in% c("snowmelt", "ROS"))
b1_fit  <- glm(I(gmm_class == "snowmelt") ~ rain_frac + swe_log,
               data = b1_data, family = binomial)

B1_INTERCEPT_check <- -coef(b1_fit)[[1]] / coef(b1_fit)[[3]]
B1_SLOPE_check     <- -coef(b1_fit)[[2]] / coef(b1_fit)[[3]]

               data = b2_data, family = binomial)
```

### Data used

| Dimension | Value |
|---|---|
| Sites | Unregulated only (`!regulated` in `site_metadata.rds`) |
| Peaks | Deduplicated on `(site_no, peak_id)`; `!is.na(rain_frac)` and `!is.na(swe_mean_mm)` |
| Features for GMM | Scaled `rain_frac` and `log10(swe_mean_mm + 1)` |
| Features for logistic | **Unscaled** `rain_frac` and `log10(swe_mean_mm + 1)` |
| Labels | Merged GMM class assignment (`gmm_class`), not `flood_type_raw` |
| Class sizes | Rainfall >> Snowmelt >> ROS (severe imbalance) |

### Why a prior reproduction attempt likely failed

The most common causes of 50–100% coefficient divergence with similar agreement metrics are:

1. **Wrong features** — fitting on scaled rather than unscaled `(rain_frac, log10_swe)`.
   The GMM uses scaled inputs; the logistic regression uses raw values. Mixing these
   produces coefficients in the wrong units.

2. **Wrong labels** — using `flood_type_raw` (current classification) instead of
   `gmm_class` (merged GMM assignment). For the majority of peaks these agree, but
   the ROS boundary is sensitive to the small fraction that differ.

3. **Wrong model structure** — fitting a single 3-class multinomial logistic model
   rather than two sequential binary models on different data subsets.

4. **Convergence** — class imbalance (especially ROS ≪ rainfall) can cause logistic
   regression to fail to converge or converge to a numerically different saddle point.
   LDA is immune to this; if B1 coefficients are stable but B2 is not, try
   `MASS::lda()` on the `{ROS, rainfall}` subset as an alternative for B2.

## Note on LDA vs. logistic regression for this problem

For well-separated classes with approximately Gaussian within-class distributions, LDA
and logistic regression produce the same linear boundary asymptotically. The fact that
`lda_boundaries.png` exists suggests LDA was used as a cross-check; the logistic result
was chosen as the canonical one (it appears in the 6b header comment and in the figure
referenced from that script). If the reconstruction above does not reproduce the
coefficients exactly, try fitting `MASS::lda(gmm_class ~ rain_frac + swe_log, data = ...)` 
on each binary subset and extracting the discriminant function coefficients instead.
